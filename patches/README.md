# 关于 11-128

`patch_11-128.py` 是**必须打**的补丁。这里记一下为什么，以及我们走过的一个大弯路。

## 它解决什么

国内上游对"不像官方客户端"的请求返回：

```
400 {"code":11-128,"msg":"Illegal API invocation from an unapproved channel"}
```

DSH 系统提示词里有两段话会触发它，补丁在网关出站前把它们换成同义说法。

## 大弯路：判断条件写成了"改写后的话"

补丁里有一段 `sanitize_dsh_prompt()`，它靠两个 `if ... in text` 判断要不要改：

```python
if "Tokens prefixed with @ are paths" in text:      # ← 这是"原文"
    ...
if "talking to the user through the agent's Web GUI" in text:   # ← 这是"原文"
```

**这两个条件必须匹配 DSH 真正发出来的原文。**

我们曾经把它当成 bug"修"了一次，改成匹配**改写后的措辞**。
结果条件永远不成立 → 清洗静默失效 → 真实请求带着原话发出去 →
**所有请求 100% 报 11-128**，流量全掉到付费中转站。

## 实测数据

| 时间段 | 网关里的清洗 | 结果 |
|---|---|---|
| 14:00 – 15:19 | 正常生效 | 290+ 次成功，0 失败 |
| 15:19 – 15:53 | 条件被改错，静默失效 | **0 成功，172 次失败全是 11-128** |
| 15:56 – 16:00 | 整段删掉 | 仍然全挂（删掉 = 不清洗，一个效果） |
| 16:00 之后 | 恢复原版 | 真实 DSH 提示词回放，3 项全 200 |

## 所以

- 这个补丁**必须装**
- 改它之前，先用 `check_sanitize.py` 跑一遍，确认 `有改写吗: True`
- 判断条件永远匹配**原文**，别match改写后的结果
- 如果哪天 DSH 升级换了提示词措辞，补丁会静默失效 —— 症状就是 11-128 回来，
  这时候更新 guard 里的字符串即可，逻辑不用动
